## 1. Konteks & Masalah (Context)
DomiBox membutuhkan mail server engine untuk menangani penerimaan email masuk (*inbound SMTP*) pada Port 25, validasi SPF/DKIM/DMARC, penyimpanan pesan, dan eksposur API modern untuk manajemen mailbox dan penarikan pesan. Server email ini harus dapat berjalan stabil pada VPS Linux dengan RAM 3.6 GiB, mendukung multi-domain dinamis, dan memiliki antarmuka integrasi yang tidak memerlukan restart layanan saat penambahan domain atau alias baru.

Hasil riset infrastruktur awal (`docs/09-research/mail-infrastructure-suitability.md`) mengidentifikasi bahwa solusi email tradisional multi-kontainer (seperti Mailu, Mailcow, atau iRedMail) mengonsumsi memori berlebih (>1.5–2.5 GiB RAM) yang akan membuat VPS pilot kehabisan memori. Di sisi lain, mail transfer agent (MTA) sederhana seperti Haraka atau Postfix murni memerlukan banyak komponen tambahan untuk penyimpanan dan API.

---

## 2. Faktor Pendorong Keputusan (Decision Drivers)
1. **Jejak Memori (Memory Footprint):** Engine email wajib beroperasi di bawah ~250 MB RAM saat beban stabil (`NFR-001`, `capacity-planning.md`).
2. **Dukungan Protokol Modern (JMAP / HTTP API):** Memerlukan protokol terstruktur berbasis HTTP (JMAP RFC 8620/8621) untuk memanipulasi alias, akun, dan pesan secara programatik tanpa parsing log teks atau manipulasi database mail server secara mentah (`BR-001`, `FR-001`).
3. **Multi-Domain Dinamis Tanpa Restart:** Penambahan domain atau mailbox baru harus aktif seketika tanpa me-reload proses Postfix/Dovecot (`DOM-001`, `MBX-001`).
4. **Lisensi & Kedaulatan Kode:** Berlisensi open-source ramah self-hosted tanpa melanggar batasan hukum integrasi sistem (`DEC-001`).

## 3. Pilihan yang Dipertimbangkan (Options Considered)

| Kriteria Evaluasi | Opsi 1: Stalwart Mail Server v1.0.3 (Dipilih) | Opsi 2: Mailu (Postfix + Dovecot + Rspamd) | Opsi 3: Haraka SMTP + Custom Storage Backend |
| --- | --- | --- | --- |
| **Bahasa & Arsitektur** | Rust (All-in-one binary single-process) | Python/C/Lua (Multi-container stack 7+ container) | Node.js (Plugin-based SMTP receiver only) |
| **Konsumsi RAM Idle/Load** | **~120–180 MB** (Sangat ringan dan efisien) | >1.5–2.0 GiB (Rentan OOM pada RAM 3.6 GiB) | ~150 MB (Hanya SMTP, butuh Dovecot terpisah) |
| **API Manajemen Bawaan** | **JMAP RFC 8620 + REST Management API** | REST API terbatas / Admin Web UI | Tidak ada API bawaan (harus buat custom plugin) |
| **Dukungan Multi-Domain** | Native, dinamis via directory/API | Didukung via SQLite/Postgres admin | Didukung manual via file konfigurasi/lookup DB |
| **Lisensi** | AGPL-3.0 (Community Edition) | MIT / BSD | MIT |
| **Catatan Fitur Riset (`F2`)** | *Masked Email* adalah fitur Enterprise; Community menggunakan *virtual alias* + *catch-all* | Memiliki fitur alias standard | Tidak memiliki fitur mailbox/storage bawaan |

## 4. Keputusan yang Diambil (Decision Outcome)
Memilih **Opsi 1: Stalwart Mail Server v1.0.3 Community Edition**.

Stalwart dipilih sebagai mail engine resmi DomiBox karena dibangun di atas bahasa Rust dengan efisiensi memori luar biasa (~150 MB RAM), menggabungkan SMTP, IMAP, JMAP, dan filter anti-spam dalam satu kontainer tunggal.

**Kebijakan Khusus Berdasarkan Temuan Riset (`F2`):**
Karena fitur *Masked Email* bawaan Stalwart hanya tersedia pada edisi Enterprise berbayar, DomiBox akan menggunakan primitif yang tersedia secara gratis pada edisi Community, yaitu:
- Pembuatan dan penghapusan *virtual alias* dinamis via API JMAP/Management.
- Konfigurasi *catch-all virtual mailbox* per domain untuk penerimaan fleksibel.
- Kontrol siklus hidup TTL mailbox sementara dikelola langsung oleh background scheduler aplikasi DomiBox (`ADR-003`).

## 5. Konsekuensi Positif & Negatif (Consequences)
### Konsekuensi Positif:
- **Penghematan Memori Ekstrem:** Menghemat >1.3 GiB RAM dibandingkan Mailu/Mailcow, menjamin kestabilan VPS 3.6 GiB.
- **Protokol Masa Depan (JMAP):** Manipulasi pesan email berbasis query JSON terstandarisasi RFC 8620/8621, menggantikan kerumitan parsing koneksi socket IMAP.
- **Single Binary Contained:** Tidak ada ketergantungan pada 5-10 container pendukung (tidak perlu Rspamd, ClamAV, Redis terpisah untuk mail filter dasar).

### Konsekuensi Negatif & Mitigasi:
- *Batasan Lisensi AGPL-3.0:* Stalwart berlisensi AGPL-3.0.
  - *Mitigasi:* Stalwart dijalankan murni sebagai service kontainer terisolasi (*over-the-network service*) yang diakses via jaringan HTTP/JMAP standar. Tidak ada penautan kode sumber (*no code linking/compilation*) antara DomiBox Core dan Stalwart, sehingga kode DomiBox tetap independen dan patuh lisensi.
- *Ketergantungan Ekosistem Relatif Baru:* Stalwart lebih baru dibanding Postfix/Dovecot yang telah berusia puluhan tahun.
  - *Mitigasi:* Dilakukan pengujian PoC performa dan ketahanan memori sebagai gerbang teknis (*Technical Spike* `EPIC-12`) sebelum cutover rilis.
