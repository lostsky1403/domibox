## 1. Konteks & Masalah (Context)
DomiBox membutuhkan penyimpanan data persisten untuk domain terdaftar, mailbox, metadata email masuk, kode OTP terekstraksi, sesi login pemilik, konfigurasi pairing Telegram, serta jejak audit (*audit logs*).

Karakteristik beban kerja:
- Tingkat baca/tulis moderat untuk single-owner (~beberapa puluh transaksi per menit).
- Memerlukan integritas referensial kuat (cascade delete mailbox ke pesan, domain ke mailbox).
- Memerlukan dukungan tipe data semi-terstruktur (JSONB) untuk menyimpan header MIME dan detail payload audit.
- Sesuai dengan batas memori VPS 3.6 GiB RAM.

---

## 2. Faktor Pendorong Keputusan (Decision Drivers)
1. **Keandalan Transaksi ACID:** Mencegah kondisi inkonsisten saat mailbox kedaluwarsa atau terjadi auto-purge konkuren (`BR-004`, `OPS-001`).
2. **Kueri JSONB Tingkat Lanjut:** Mendukung pengindeksan GIN pada payload header email dan metadata audit (`FR-005`, `SEC-007`).
3. **Efisiensi Memori:** Mesin basis data dapat dikonfigurasi untuk berjalan stabil di bawah ~150 MB RAM (`NFR-001`, `capacity-planning.md`).
4. **Ekosistem Migrasi & ORM Matang:** Kompatibel dengan alat migrasi schema terkemuka (Kysely / Prisma / Drizzle) (`ADR-006`).

---

## 3. Pilihan yang Dipertimbangkan (Options Considered)

| Parameter Evaluasi | Opsi 1: PostgreSQL 16 Alpine (Dipilih) | Opsi 2: SQLite3 (Embedded in-process) | Opsi 3: MongoDB / NoSQL Document Store |
| --- | --- | --- | --- |
| **Konsumsi Memori** | Terukur & Dapat Dibatasi (~100–120 MB dengan tuned shared_buffers) | Sangat Ringan (~15 MB) | Sangat Tinggi (>300–500 MB RAM default) |
| **Integritas Relasional** | ACID Penuh, Foreign Keys, Strict Types | ACID Single-writer, WAL mode | Eventual consistency, No real FKs |
| **Konkurensi Tulis** | Multi-process concurrent write tinggi | Terbatas (Database locked saat worker dan API menulis bersamaan) | Tinggi |
| **Dukungan Tipe JSON** | Native JSONB dengan GIN Index | JSON string biasa (fungsi json terbatas) | Native BSON |
| **Backup & Pemulihan** | Sangat matang (`pg_dump`, point-in-time) | Sederhana (copy file), rawan korup saat proses crash | Butuh dump tool khusus |

## 4. Keputusan yang Diambil (Decision Outcome)
Memilih **Opsi 1: PostgreSQL 16 (Image: `postgres:16-alpine`)**.

Konfigurasi resource tuning untuk VPS 3.6 GiB RAM:
- `shared_buffers = 64MB`
- `work_mem = 4MB`
- `maintenance_work_mem = 16MB`
- `max_connections = 50`
- `effective_cache_size = 256MB`
Dengan tuning ini, konsumsi memori PostgreSQL stabil di kisaran **~100–120 MB**, menjamin performa indeks GIN untuk JSONB tetap kencang tanpa mengorbankan RAM sistem.

## 5. Konsekuensi Positif & Negatif (Consequences)
### Konsekuensi Positif:
- Keamanan transaksi tinggi untuk operasi batch auto-purge data kedaluwarsa.
- Kemudahan query laporan statistik, pencarian subjek email, dan audit log berbasis waktu.
- Ekosistem tooling database terluas di dunia industri perangkat lunak.

### Konsekuensi Negatif & Mitigasi:
- *Menambah 1 container terpisah:* Sedikit lebih kompleks dibanding SQLite single-file.
  - *Mitigasi:* Dikelola otomatis via `docker-compose.yml` dengan healthcheck dependensi teratur.
