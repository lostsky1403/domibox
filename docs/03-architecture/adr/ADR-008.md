## 1. Konteks & Masalah (Context)
DomiBox memiliki bot Telegram sebagai antarmuka kedua untuk membuat sementara mailbox, menampilkan inbox terbaru, mengambil kode OTP, dan menerima notifikasi instan.

Persyaratan teknis bot:
- Dapat berjalan sebagai service terpisah dalam modular monolith tanpa konflik port dengan API Fastify.
- Memiliki sistem authorize dan izin berbasis *owner allowlist* (daftar Telegram user ID).
- Mendukung konversi format pesan Telegram menjadi payload internal yang konsisten dengan Web Dashboard (`SEC-005`, `BOT-001`).

---

## 2. Faktor Pendorong Keputusan (Decision Drivers)
1. **Fitur Middleware Canggih:** Dukungan konversi session (memori atau file), filter update Telegram, dan rate limiting bawaan.
2. **TypeScript Native:** API berjenis lengkap untuk menerjemahkan nama perintah (`/create`, `/otp`, `/inbox`) ke handler langsung dengan aman.
3. **Konsumsi Memori Ringan:** Perpustakaan bot harus kecil dan efisien agar dapat berbagi RAM dengan container lain di VPS 3.6 GiB (`NFR-001`).

---

## 3. Pilihan yang Dipertimbangkan (Options Considered)

| Parameter Evaluasi | Opsi 1: grammY (Dipilih) | Opsi 2: Telegraf | Opsi 3: Python Aiogram |
| --- | --- | --- | --- |
| **Bahasa Runtime** | TypeScript/Node.js | TypeScript/Node.js | Python |
| **Middleware Architecture** | Komposisi middleware modern berbasis generator | Middleware dari model lama (callback-style) | Penyimpanan state callback complex |
| **Ruang Lingkup Fitur** | Dukungan session bawaan + filter structure + FSM | Dukungan session + FSM | Sangat komprehensif |
| **Ekosistem Interop** | Selaras penuh dengan backend Fastify/TypeScript | Selaras penuh dengan backend Fastify | Perlu servis terpisah Python runtime tambahan |

---

## 4. Keputusan yang Diambil (Decision Outcome)
Memilih **Opsi 1: grammY**.

grammY dipilih karena:
- API-nya yang ergonomis dan diracik khusus untuk TypeScript modern.
- Memiliki fitur session storage + rate limiter plugin integrasi mulus.
- Tidak membutuhkan runtime kedua (seperti Python), sehingga logika bisnis Telegram dapat berbagi pustaka TypeScript yang sama dengan backend API (`docs/04-technical/integration-contracts.md`).

---

## 5. Konsekuensi Positif & Negatif (Consequences)
### Konsekuensi Positif:
- Satu bahasa pemrograman (TypeScript) untuk seluruh layanan backend & bot.
- Pengerjaan perubahan logika bisnis (contoh: aturan validasi OTP) hanya perlu dilakukan sekali untuk kedua antarmuka.

### Konsekuensi Negatif & Mitigasi:
- *Sesi Bot disimpan di memori tunggal:* Jika proses restart, sesi aktif pengguna hilang.
  - *Mitigasi:* Sesi bot disimpan ke PostgreSQL table `telegram_sessions` yang tahan lama. Telegram user juga harus melakukan otentikasi ulang setelah terjadi *restart* service (`SEC-005`).

## 6. Keterkaitan Kebutuhan (Traceability)
- **Kebutuhan Fungsional:** `FR-006` (`BOT-001` s/d `BOT-005`)
- **Kebutuhan Non-Fungsional:** `NFR-001` (Memory), `NFR-002` (Latency <1.5s)
- **Kebutuhan Keamanan:** `SEC-005` (Owner allowlist), `SEC-006` (Telegram identity binding)
