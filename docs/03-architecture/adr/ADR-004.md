# ADR-004: Protokol Integrasi Mail Server (JMAP over HTTP vs IMAP/SMTP)

---

## 1. Konteks & Masalah (Context)
Aplikasi backend DomiBox perlu berinteraksi dengan mail server engine (Stalwart) untuk dua kebutuhan utama:
1. Operasi manajemen: Mendaftarkan domain, menambahkan/menghapus alias email, dan memantau status akun.
2. Penarikan pesan: Membaca email masuk, mengambil struktur MIME/body, dan menghapus pesan setelah di-purge.

Secara historis, aplikasi email berinteraksi melalui kombinasi IMAP (RFC 3501) untuk membaca pesan dan SMTP submission (RFC 6409) untuk mengirim. Namun, IMAP adalah protokol *stateful*, berbasis koneksi TCP persisten, menggunakan format teks kompleks, dan boros energi pada jaringan seluler. Stalwart mendukung **JMAP (JSON Meta Application Protocol, RFC 8620/8621)** yang berjalan di atas HTTP/JSON stateless.

---

## 2. Faktor Pendorong Keputusan (Decision Drivers)
1. **Ergonomi Pengembangan:** Menggunakan payload JSON terstruktur standar REST/HTTP yang mudah dikonsumsi oleh runtime Node.js/TypeScript (`FR-004`).
2. **Efisiensi Sumber Daya Server:** Menghindari pemeliharaan pool koneksi TCP *long-lived* IMAP yang boros memori dan rentan *timeout* atau *socket hang* (`NFR-001`).
3. **Kemampuan Batching:** JMAP mendukung pemanggilan multi-metode dalam satu request HTTP tunggal (`jmap/call`), mengurangi round-trip latensi jaringan (`NFR-004`).

---

## 3. Pilihan yang Dipertimbangkan (Options Considered)

| Parameter Evaluasi | Opsi 1: JMAP over HTTP/JSON (Dipilih) | Opsi 2: Klien IMAP Tradisional (node-imap/imapflow) | Opsi 3: Akses Langsung Basis Data Stalwart |
| --- | --- | --- | --- |
| **Gaya Komunikasi** | Stateless HTTP/1.1 atau HTTP/2 JSON | Stateful TCP Socket persisten | Direct SQL/RocksDB queries |
| **Format Payload** | JSON murni (RFC 8620) | Sintaksis IMAP tokenized string / atom | Baris database mentah |
| **Kestabilan Koneksi** | Sangat Tinggi (Standard HTTP Keep-Alive/Pooling) | Sedang (Perlu rekoneksi berkala, IDLE command handling) | Terikat skema internal DB |
| **Isolasi Arsitektur** | Sangat Bersih (API contract publik terstandar IETF) | Bersih (Protokol standar IETF) | Buruk (Kopling ketat ke skema DB pihak ketiga) |

---

## 4. Keputusan yang Diambil (Decision Outcome)
Memilih **Opsi 1: JMAP over HTTP (RFC 8620/RFC 8621)** sebagai protokol integrasi resmi antara DomiBox Core dan Stalwart Mail Server.

Proses integrasi:
- DomiBox menggunakan HTTP client (`undici` / native `fetch`) untuk memanggil endpoint JMAP Stalwart (`http://stalwart:8080/jmap`) dengan Bearer Token administratif.
- Operasi pembuatan dan penghapusan alias dilakukan via JMAP Core method.
- Penarikan pesan email baru dilakukan via `Email/get` dan `Email/query` dengan filter waktu dan mailbox ID.

---

## 5. Konsekuensi Positif & Negatif (Consequences)
### Konsekuensi Positif:
- Tidak membutuhkan pustaka driver IMAP pihak ketiga yang berat dan rentan kebocoran memori.
- Penanganan error berbasis kode status HTTP standar dan error envelope JMAP yang deterministik.
- Mendukung pengambilan parsed text dan HTML langsung dari engine tanpa harus melakukan parsing streaming manual yang rumit.

### Konsekuensi Negatif & Mitigasi:
- *JMAP relatif baru:* Dokumentasi pustaka JMAP JavaScript masih lebih sedikit dibanding IMAP.
  - *Mitigasi:* DomiBox membangun wrapper klien JMAP internal yang sangat terfokus (*lean typed client*) untuk metode-metode yang dibutuhkan saja (`docs/04-technical/integration-contracts.md`).
