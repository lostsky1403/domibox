# ADR-010: Strategi Inbound SMTP Native dan Delegasi DNS (Cloudflare + Port 25)

## 1. Konteks & Masalah (Context)
DomiBox membutuhkan kemampuan untuk menerima email dari server pengirim eksternal manapun di internet. Penerimaan email secara standar bergantung pada protokol SMTP yang beroperasi di **TCP Port 25**.

Riset infrastruktur awal menemukan temuan krusial (`F1`):
- Tencent Cloud CVM memblokir lalu lintas **outbound** TCP Port 25 secara default.
- **Inbound** TCP Port 25 tidak diblokir oleh penyedia cloud, melainkan sepenuhnya dikendalikan oleh Security Group dan UFW pada instance.
- VPS tidak memiliki IP v6 publik (`F5`), sehingga penerimaan hanya pada IPv4.

DNS domain pilot `sintaksis.biz.id` dikelola di Cloudflare (`F6`).

---

## 2. Faktor Pendorong Keputusan (Decision Drivers)
1. **Penerimaan Email Universal:** DomiBox harus dapat menerima email dari penyedia layanan manapun (Gmail, Outlook, layanan OTP bank, dll.) tanpa bergantung pada relay pihak ketiga (`BR-001`).
2. **Kepatuhan Standar SPF/DKIM/DMARC:** DNS harus dikonfigurasi dengan benar untuk memvalidasi dan melindungi domain pilot dari pemalsuan identitas.
3. **Biaya Nol & Kedaulatan Penuh:** Menghindari ketergantungan pada layanan penerimaan email berbayar pihak ketiga untuk fungsi dasar.

---

## 3. Pilihan yang Dipertimbangkan (Options Considered)

| Parameter Evaluasi | Opsi 1: Native Inbound SMTP (Port 25) + Cloudflare DNS Only (Dipilih) | Opsi 2: Cloudflare Email Routing (Forward ke webhook/worker) | Opsi 3: Layanan SMTP Relay Inbound Berbayar (Mailgun, SendGrid Inbound Parse) |
| --- | --- | --- | --- |
| **Ketersediaan di Tencent** | **Tersedia** (Inbound 25 terbuka via SG/UFW) | Tersedia (via Cloudflare) | Tersedia (via HTTPS webhook) |
| **Biaya Operasional** | Gratis (hanya biaya VPS) | Gratis (batas limit Cloudflare) | Berbayar per volume |
| **Kompatibilitas & Kontrol Penuh** | **100%** (Kontrol penuh header, MIME, bounce) | Terbatas (Email diteruskan sebagai parsed format Cloudflare) | Terbatas pada format parsing vendor |
| **Kerumitan DNS** | Standar (A, MX, PTR, SPF, DKIM, DMARC) | Sederhana (MX diarahkan ke Cloudflare) | Bervariasi |

---

## 4. Keputusan yang Diambil (Decision Outcome)
Memilih **Opsi 1: Native Inbound SMTP pada Port 25** dengan pengelolaan DNS via Cloudflare (mode **DNS Only / Grey Cloud** untuk record MX dan A mail server).

Rincian implementasi:
- **Tencent Security Group:** Buka inbound TCP port 25 dari `0.0.0.0/0`.
- **UFW (Ubuntu):** Izinkan `25/tcp`, `587/tcp` (future submission), `80/tcp`, `443/tcp`. Tolak lainnya.
- **Cloudflare DNS:**
  - Record `A` untuk `mail.sintaksis.biz.id` → IP publik VPS (DNS Only, tanpa proxy orange).
  - Record `MX` untuk `sintaksis.biz.id` → `mail.sintaksis.biz.id` (prioritas 10).
  - Record `TXT` SPF: `v=spf1 mx -all`.
  - Record `TXT` DMARC: `v=DMARC1; p=quarantine; rua=mailto:...`.
  - Record `TXT` DKIM: Dihasilkan oleh Stalwart dan dipublikasikan.
- **Reverse DNS (PTR):** Diajukan ke Tencent Cloud (jika didukung) agar IP VPS memetakan balik ke `mail.sintaksis.biz.id`.
- **Outbound SMTP:** Tetap tidak dapat digunakan pada fase MVP karena blokir outbound port 25 oleh Tencent (`F1`). Fitur pengiriman email keluar ditunda ke fase lanjutan dengan SMTP relay eksternal.

---

## 5. Konsekuensi Positif & Negatif (Consequences)
### Konsekuensi Positif:
- Kendali penuh atas pipeline penerimaan email (parsing, validasi, bounce handling).
- Tidak bergantung pada batas kuota atau ketersediaan layanan email pihak ketiga.
- Kompatibel universal dengan semua server pengirim di internet.

### Konsekuensi Negatif & Mitigasi:
- *Outbound SMTP diblokir:* Tidak dapat mengirim email keluar (balasan, forward) dari VPS.
  - *Mitigasi:* Fitur outbound tidak termasuk dalam cakupan MVP (`FR-003`/outbound dicatat sebagai fase lanjutan). Jika diperlukan, gunakan relay SMTP eksternal (Amazon SES, Mailgun) melalui port 587/465.
- *Reputasi IP baru:* IP VPS baru berisiko masuk spam filter penerima.
  - *Mitigasi:* Konfigurasi SPF, DKIM, DMARC yang benar; pemantauan blacklist IP secara berkala.
