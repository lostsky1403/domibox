## 1. Konteks & Masalah (Context)
DomiBox adalah platform manajemen email multi-domain mandiri (*self-hosted*) untuk pemilik tunggal (*single-owner*), yang mencakup pengelolaan domain, siklus hidup mailbox sementara dan permanen, penerimaan email inbound, ekstraksi OTP instan, antarmuka Web Dashboard SPA, serta Bot Telegram.

Infrastruktur target awal yang telah diverifikasi adalah VPS Tencent Cloud Ubuntu 24.04 LTS dengan spesifikasi terbatas: **2 vCPU AMD EPYC 7K62, ~3.6 GiB RAM fisik, ~1.9 GiB Swap, dan ~50 GiB sisa disk**. Tim perlu menentukan gaya arsitektur aplikasi (*architectural style*) dan model deployment yang meminimalkan *overhead* konsumsi memori/CPU, mudah dipelihara oleh satu insinyur, namun tetap memiliki batas-batas modul (*module boundaries*) yang bersih dan dapat dievolusikan ke arsitektur terdistribusi jika dibutuhkan di masa mendatang.

---

## 2. Faktor Pendorong Keputusan (Decision Drivers)
1. **Keterbatasan Sumber Daya:** Alokasi memori untuk seluruh stack aplikasi DomiBox tidak boleh melebihi ~600 MB agar sisa RAM cukup untuk Stalwart Mail Server (~150 MB), PostgreSQL 16 (~120 MB), Caddy reverse proxy (~40 MB), dan sistem operasi Ubuntu (~600 MB) (`NFR-001`, `capacity-planning.md`).
2. **Kecepatan Pengiriman MVP:** Menghindari kompleksitas orkestrasi jaringan antar-layanan (*service mesh*, distributed tracing, multi-repo CI/CD, remote gRPC/Kafka overhead) pada fase awal (`GOAL-001`, `BR-001`).
3. **Kemandirian & Kemudahan Deployment:** Cukup dijalankan menggunakan `docker compose up -d` tanpa memerlukan Kubernetes, Nomad, atau cluster eksternal.
4. **Batas Domain Bersih:** Setiap modul fungsional (Domain, Mailbox, Inbound, OTP, Notification, Audit) harus memiliki domain model, use-case interactor, dan penyimpanan data terisolasi secara logis (*in-process boundary*).

## 3. Pilihan yang Dipertimbangkan (Options Considered)

| Parameter Evaluasi | Opsi 1: Microservices Multi-Container | Opsi 2: Modular Monolith + Docker Compose (Dipilih) | Opsi 3: Monolith Tradisional Tanpa Struktur Modul |
| --- | --- | --- | --- |
| **Konsumsi RAM Total** | Sangat Tinggi (>1.8 GiB karena banyak runtime Node/Go) | Rendah & Terprediksi (~120–180 MB untuk single runtime Fastify) | Rendah (~120 MB) |
| **Overhead Orkestrasi** | Tinggi (Butuh service discovery, network mesh, multi-compose) | Sangat Rendah (1 container backend core + DB + Mail Server) | Sangat Rendah (1 container backend) |
| **Integritas Batas Modul** | Sangat Ketat (Terpisah proses fisik) | Ketat (Enforced via TypeScript project references & directory conventions) | Buruk (*Spaghetti code*, tight coupling tinggi) |
| **Kesesuaian VPS Pilot** | Tidak Layak (Rentan OOM killer pada 3.6 GiB RAM) | **Sangat Sesuai** (Jejak memori ramah lingkungan) | Sesuai secara resource, buruk secara evolusi |
| **Jalur Evolusi Masa Depan** | Sudah terpisah | Sangat Mudah (Modul dapat diekstrak menjadi service mandiri) | Sangat Sulit untuk di-refactor |

## 4. Keputusan yang Diambil (Decision Outcome)
Memilih **Opsi 2: Arsitektur Modular Monolith Berbasis Docker Compose**.

Aplikasi backend DomiBox dibangun sebagai satu kesatuan proses (*single deployable unit*) menggunakan Node.js LTS dan Fastify dengan pembagian modul logika yang ketat:
- `modules/domain`: Registrasi, validasi token, dan verifikasi DNS MX/TXT.
- `modules/mailbox`: Lifecycle mailbox sementara (TTL) dan permanen, penomoran alias, kuota.
- `modules/inbound`: Ingestion email RFC822, parsing MIME, penyimpanan EML.
- `modules/otp`: Engine regex ekstraksi OTP dan deteksi tautan aktivasi.
- `modules/notification`: Dispatcher notifikasi multi-kanal (Telegram Bot & SSE/Webhooks).
- `modules/scheduler`: Background worker untuk TTL expiry check dan auto-purge.
- `modules/auth`: Sesi pemilik, verifikasi TOTP/Passkey, guard middleware.

Seluruh modul berkomunikasi *in-process* melalui typed event emitter atau domain interfaces, tanpa latensi jaringan internal.

## 5. Konsekuensi Positif & Negatif (Consequences)
### Konsekuensi Positif:
- **Jejak Memori Sangat Hemat:** Menghemat hingga ~1 GiB RAM dibandingkan microservices, menjaga margin keamanan terhadap OOM Killer pada VPS 3.6 GiB.
- **Transaksionalitas Sederhana:** Modul dapat memanfaatkan transaksi ACID lokal PostgreSQL jika diperlukan konsistensi ketat (misal: mailbox creation + initial alias audit log).
- **Pengujian Cepat:** Unit test dan integration test dapat dijalankan instan dalam satu proses tes tanpa perlu mocking jaringan kompleks.
- **Operasional Sederhana:** Satu set file `docker-compose.yml` mencakup seluruh stack layanan.

### Konsekuensi Negatif & Mitigasi:
- *Risiko Spaghetti Coupling:* Jika disiplin kode longgar, ketergantungan antar-modul bisa mengabur.
  - *Mitigasi:* Menggunakan ESLint boundaries plugin dan arsitektur *Ports and Adapters* (Hexagonal), di mana dependensi hanya boleh mengarah ke Domain Interactor.
- *Single Point of Failure:* Crash pada satu modul (misal memory leak parser MIME) dapat mematikan seluruh proses core API.
  - *Mitigasi:* Restart policy Docker `unless-stopped`, healthcheck container, dan penanganan parsing MIME dalam boundary `try-catch` dengan isolasi alokasi buffer.
